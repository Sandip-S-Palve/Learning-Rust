Strings and slices

Learning objectives

  • Choose between String and &str, and explain what each is in memory
  • Count text correctly in bytes, chars and grapheme clusters, and explain why Rust strings can't be indexed by position
  • Slice strings and other collections safely, using &[T], &str, get and char boundaries
  • Write functions that accept any text or any run of values, through deref coercion, and return borrowed or owned data with Cow
  • Compare Rust's UTF-8 strings with .NET's UTF-16 string, Span<T>, culture rules and StringBuilder

Why this matters

💡 Why this matters

Text is most of what a rule engine handles: rule definitions, field names, operators, values, error messages. A workflow engine moves JSON payloads, step names and logs. In C# you mostly don't think about it. string is one immutable type, Substring copies, the garbage collector cleans up, and s[i] works (until a user types an emoji).

Rust makes you see two things C# hides. First, who owns the text: an owned, growable String, or a borrowed view &str into text that lives somewhere else. Second, what text is: Rust strings are UTF-8 bytes, so "length" and "the third character" stop being simple questions. Both pay off. Borrowed slices let you parse ten thousand rules while allocating almost nothing (Lab step 5 measures 1,003 allocations against 170,000). And the encoding rules turn a whole class of "works in testing, breaks on Ærøskøbing" bugs into compile errors or explicit choices.

Intuition first: the document and the highlighter

🧭 Analogy

Keep the document metaphor from chapters 2.2 and 2.3.

  • String is a document you own, on a notepad with spare pages. You can write more on it; when the pad is full you copy everything onto a bigger pad and throw the old one away.
  • &str is a highlighter mark on someone's document: "from here, this many letters". It owns nothing and copies nothing. It can mark all of a String, part of one, or text printed permanently in the program itself (a literal).
  • Slices in general (&[T]) are the same highlighter for any row of values: part of an array, part of a Vec.
  • UTF-8 means the letters have different widths. "a" takes one square of the page, "é" two, "👍" four. You can't jump to "the 7th letter" without counting from the start, and a highlighter can't start in the middle of a letter.

C#'s string is closer to a laminated card: immutable, shared by reference, and written in UTF-16, where most letters take one square but emoji take two. ReadOnlySpan<char> is C#'s highlighter, and the nearest thing it has to &str.

C#
string rule = "amount > 100";     // immutable, UTF-16
string field = rule.Substring(0, 6); // allocates a copy
ReadOnlySpan<char> view = rule.AsSpan(0, 6); // no copy
var sb = new StringBuilder(rule);   // mutable buffer
sb.Append(" AND vip");
char c = rule[0];                   // a UTF-16 code unit
int n = rule.Length;                // UTF-16 code units
Rust
let rule: &str = "amount > 100";   // borrowed, UTF-8, 'static
let field: String = rule[0..6].to_string(); // explicit copy
let view: &str = &rule[0..6];       // no copy
let mut sb = String::from(rule);    // owned, growable
sb.push_str(" AND vip");
let c = rule.chars().next();        // Option<char>; no rule[0]
let n = rule.len();                 // BYTES, not characters

Core explanation

Basic

String and &str

A String owns its text. The Book's description is exact: "A String is a wrapper over a Vec<u8>": a pointer, a length and a capacity on the stack (24 bytes), pointing at a heap buffer of bytes it can grow, which is guaranteed to be valid UTF-8. When the String is dropped, the buffer is freed (chapter 2.2).

A string slice, &str, borrows text. The standard library: "The str type, also called a 'string slice', is the most primitive string type. It is usually seen in its borrowed form, &str." And "A &str is made up of two components: a pointer to some bytes, and a length." It can point into a String's buffer, into another slice, or at a string literal. Literals have type &'static str: their bytes are stored in the compiled program and live as long as it runs (the 'static lifetime, chapter 2.11).

The rule for when to use which is the ownership rule from 2.2 and 2.3: store and return String; accept &str. A struct field that must keep its text owns a String. A function that only reads text takes &str, and then accepts every kind of text, as the next section shows.

let a: String = String::from("vip");     // &str -> String (copies)
let b: String = "vip".to_string();       // the same, via Display
let c: String = format!("{a} tier {}", 2); // build from pieces
let d: &str = &a;                        // String -> &str (free: &String coerces)
let e: &str = a.as_str();                // the same, explicitly
let f: String = d.to_owned();            // &str -> String again (copies)
println!("{a} {b} {c} {d} {e} {f}");

Slices in general: &[T]

&str is one case of a general idea. A slice &[T] borrows a contiguous run of values: all or part of an array, a Vec, or another slice. You make one with a range: &v[1..3] (elements 1 and 2), &v[2..], &v[..2], &v[..]. &mut [T] lets you change the elements in place (sort, swap, overwrite) but never the length, since only the owner (the Vec) can grow or shrink the storage.

Both &str and &[T] are fat pointers: an address plus a length, 16 bytes on a 64-bit target, against 8 for a plain reference (Lab step 3 prints the sizes). The length is what makes slices safe. Indexing s[i] checks i < len and panics if it isn't; s.get(i) returns an Option instead. That's the same bounds check as C#, but here it travels with every slice.

Deref coercion: one parameter type for every caller

Why does fn describe(s: &str) accept &my_string, which is a &String? Because of deref coercion: String implements Deref<Target = str>, so wherever a &str is expected, the compiler turns &String into &str for free. Vec<T> does the same for &[T]. That's why the idiomatic parameter types are &str and &[T]: one signature accepts a literal, a String, part of either, an array or a Vec (Lab step 3, sections 1–2), and Clippy's ptr_arg lint flags &String and &Vec<T> parameters, as you saw in chapter 2.3. Coercion applies to references only. Passing an owned String where &str is expected is a type error, and the compiler suggests the &:

// Passing an owned String where a &str is expected.
fn shout(s: &str) -> String {
    s.to_uppercase()
}

UTF-8: bytes, chars and graphemes

Rust text is UTF-8, and the standard library promises it: "Rust libraries may assume that string slices are always valid UTF-8." UTF-8 uses 1 byte for ASCII and 2, 3 or 4 bytes for everything else. So "length" has three honest answers, and the Book names them: "there are actually three relevant ways to look at strings from Rust's perspective: as bytes, scalar values, and grapheme clusters (the closest thing to what we would call letters)."

  • Bytes: s.len() and s.bytes(). What the string occupies in memory, on disk and on the wire.
  • chars: s.chars(). A char is "a 'Unicode scalar value'", always 4 bytes in memory, and the standard library warns that "'character' isn't a well-defined concept in Unicode".
  • Grapheme clusters: what a reader sees as one character. "é" written as e + a combining accent is two chars but one grapheme cluster; 👍🏽 (thumbs up plus a skin-tone modifier) is two chars and one grapheme. The standard library doesn't segment graphemes; the unicode-segmentation crate does (Lab step 2).

The Book gives two reasons. What should s[0] return: a byte, which is rarely what you want for non-ASCII text, or a character, which can't be found without scanning? Rust "doesn't compile this code at all and prevents misunderstandings early in the development process". And "indexing operations are expected to always take constant time (O(1)). But it isn't possible to guarantee that performance with a String." So you say which one you mean: s.as_bytes()[0] for a byte, s.chars().next() or s.chars().nth(n) for a char (O(n), and you can see the loop), or &s[a..b] for a slice by byte range.

Slicing must start and end on a char boundary. Cut through the middle of a multi-byte character and the program panics at run time, with a message that names the character:

fn main() {
    let field = "café_total";
    println!("{}", &field[0..3]); // "caf": fine, ends before 'é'
    println!("{}", &field[0..4]); // ends inside 'é' (bytes 3..5): panics
}

Byte offsets you got from the string itself are always safe: the results of find, char_indices, split and friends land on boundaries. When an offset comes from outside (user input, a fixed width, a database column), use s.get(a..b), which returns None instead of panicking, or check s.is_char_boundary(i).

🟣 Coming from C#/.NET: UTF-16, Span and culture
  • .NET strings are UTF-16. Microsoft's docs on String.Length: it "returns the number of Char objects in this instance, not the number of Unicode characters". 👍🏽 has Length 4, and s[0] on it returns half of a surrogate pair (Lab step 4). C# lets you index and gives you code units; Rust refuses and makes you choose.
  • Substring copies; AsSpan borrows. Lab step 4 measured 48 bytes allocated for a 13-character Substring and 0 for AsSpan. ReadOnlySpan<char> is the C# equivalent of &str, and Span<T> of &mut [T]. Their ref struct restrictions (stack-only, no fields in classes, no capture across await) are C#'s narrower version of the borrow rules.
  • StringBuilder ↔ String. Rust's String is already the mutable builder. There's no separate immutable string type, because a &str borrow already guarantees nobody changes the text while you read it.
  • No culture in Rust's standard library. In .NET, "title".ToUpper() depends on the current culture: under tr-TR it gives TİTLE (Lab step 4). Rust's to_uppercase follows Unicode's default mapping and gives "TITLE" everywhere. Comparison (==, Ord) is always byte-wise, like StringComparison.Ordinal. For culture-aware sorting or Unicode normalization, use crates (ICU4X, unicode-normalization).
Intermediate

Building strings, and why + moves

A String grows like a Vec: when the bytes no longer fit, it allocates a bigger buffer (roughly doubling), copies the bytes across and frees the old buffer. Lab step 1 shows capacity going 0 → 8 → 16 → 32 as words are appended: the first push allocates, the growth to 16 happened in place (the allocator could extend the block), and the growth to 32 moved the bytes to a new address.

Concatenation shows ownership at work. a + b requires a String on the left and a &str on the right, and it consumes the left side, appending to its buffer instead of allocating a fresh one:

Slices and the borrow checker

A &str into a String is a borrow, so chapter 2.3's rules apply. This is the Book's own example of what they prevent:

// The Book's classic: a slice into a String, then clearing the String.
fn first_word(s: &str) -> &str {
    s.split(' ').next().unwrap_or("")
}

fn main() {
    let mut line = String::from("approve order 42");
    let verb = first_word(&line);
    line.clear(); // would leave `verb` pointing at nothing
    println!("verb: {verb}");
}

In C#, Substring sidesteps the problem by copying, and a ReadOnlySpan<char> over a string is safe because .NET strings are immutable. In Rust the text is mutable, and the borrow checker guarantees the view stays valid. The other classic mistake is returning a slice of a String the function itself just created:

// Returning a slice of a String created inside the function.
fn normalized(field: &str) -> &str {
    &field.trim().to_lowercase()
}

fn main() {
    println!("{}", normalized("  Country "));
}

to_lowercase creates a new String that dies at the end of the function, so the function must return it owned. Or, if it only sometimes needs a new string, return a Cow.

Cow: borrow when you can, own when you must

A normaliser that lowercases field names usually finds them already lowercase. Returning String allocates every time; returning &str can't work when a change is needed. Cow ("clone on write") is an enum holding either. The standard library: "a smart pointer providing clone-on-write functionality: it can enclose and provide immutable access to borrowed data, and clone the data lazily when mutation or ownership is required."

use std::borrow::Cow;

fn normalize(field: &str) -> Cow<'_, str> {
    if field.bytes().any(|b| b.is_ascii_uppercase()) {
        Cow::Owned(field.to_ascii_lowercase())   // allocate only when needed
    } else {
        Cow::Borrowed(field)                     // the common case: no allocation
    }
}

let a = normalize("amount");                     // Borrowed
let b = normalize("Amount");                     // Owned
println!("{a} {b} {}", a.len() + b.len());       // both deref to &str
let raw = [0x63, 0x61, 0x66, 0xC3];              // invalid UTF-8 at the end
println!("{}", String::from_utf8_lossy(&raw));   // a std function returning Cow

(.bytes().any(|b| …) is LINQ's Any(b => …) over the bytes; closures and iterator chains were introduced in chapter 2.3's reading note and are covered fully in chapter 2.10.)

Callers use a Cow<str> like a &str (it derefs to one) and call .into_owned() if they need a String. The standard library uses the same pattern: String::from_utf8_lossy borrows the input when it's valid UTF-8 and allocates only to insert U+FFFD replacement characters. Lab step 5 measures what borrowing and Cow save on a rule parser.

Deep dive: why UTF-8, and what the guarantee buys

UTF-8 (RFC 3629) is ASCII-compatible, has no byte-order issues, never produces a zero byte except for NUL, and is self-synchronising: from any byte you can find the start of the current character by skipping at most three continuation bytes (10xxxxxx). It's the encoding of the web, JSON, most files and most network protocols, so a UTF-8 string type means no transcoding at I/O boundaries. .NET pays a UTF-16 ⇄ UTF-8 conversion on almost every read and write, which is why it added Utf8JsonReader, u8 string literals and Utf8.IsValid.

Because every &str is valid, code that consumes text never re-checks it. The check happens once, where bytes become text: String::from_utf8(bytes) returns a Result, from_utf8_lossy replaces bad sequences, and from_utf8_unchecked skips the check but is unsafe, because creating an invalid str breaks a promise all other code relies on. The price is that UTF-16 indexing habits don't carry over. Nothing is O(1) by character, which, as Figure 2 shows, was never really true in UTF-16 either.

Deep dive: sharing immutable text with Arc<str>

A rule engine refers to the same field names ("amount", "country") from thousands of compiled rules. Cloning a String for each copies the bytes every time. Arc<str> (chapter 2.12) stores the text once, with a reference count; cloning it just increments the count, and it's 16 bytes on the stack against String's 24 (Lab step 1), with no spare capacity on the heap. Because the text is immutable, sharing it across threads is safe. Convert with Arc::from(s). Going further, an interner maps each distinct string to a small integer id (FieldId(u32)), making comparisons and hashing integer operations. Chapters 9.2–9.3 use this in the rule compiler.

Step 1 — what a String is, and how it grows

use std::mem::size_of;
use std::sync::Arc;

fn main() {
    // 1. Three ways to hold text, and their sizes on the stack.
    let literal: &'static str = "amount > 100"; // bytes live in the binary itself
    let owned: String = String::from(literal); // a heap copy that this variable owns
    let view: &str = &owned[0..6]; // a window into owned's heap buffer
    println!("1. size_of String = {}, &str = {}, Box<str> = {}, Arc<str> = {}",
        size_of::<String>(), size_of::<&str>(), size_of::<Box<str>>(), size_of::<Arc<str>>());
    println!("   literal bytes at {:p} (read-only data in the executable)", literal.as_ptr());
    println!("   owned   bytes at {:p} (heap), len {} cap {}", owned.as_ptr(), owned.len(), owned.capacity());
    println!("   view    bytes at {:p} = owned + 0, len {}: {view:?}", view.as_ptr(), view.len());
    let tail = &owned[9..];
    println!("   tail    bytes at {:p} = owned + 9: {tail:?}", tail.as_ptr());

    // 2. Building a String: it grows by reallocating, and the buffer can move.
    let mut s = String::new();
    let mut last_ptr = s.as_ptr();
    println!("2. new(): len 0 cap {} (no allocation yet)", s.capacity());
    for word in ["rule", "-", "set", " ", "v7", " ", "approved", " by finance"] {
        s.push_str(word);
        let moved = if s.as_ptr() != last_ptr { "  <- new buffer" } else { "" };
        println!("   push_str({word:?}): len {:>2} cap {:>2}{moved}", s.len(), s.capacity());
        last_ptr = s.as_ptr();
    }

    // 3. Pre-sizing avoids the reallocations.
    let mut sized = String::with_capacity(32);
    let before = sized.as_ptr();
    sized.push_str("rule-set v7 approved by finance");
    println!("3. with_capacity(32): len {} cap {}, same buffer: {}",
        sized.len(), sized.capacity(), before == sized.as_ptr());

    // 4. Other ways to make a String.
    let a = "vip".to_string();
    let b = format!("{a} == {}", true);
    let c = a + " tier"; // `+` takes `a` by value and appends in place (a is moved)
    let d: String = ["NL", "DE", "BE"].join(",");
    println!("4. {b:?} {c:?} {d:?}");
}

Step 2 — four ways to count, and slicing by byte

use unicode_segmentation::UnicodeSegmentation;

fn show(label: &str, s: &str) {
    let bytes = s.len(); // len() counts BYTES
    let chars = s.chars().count(); // Unicode scalar values
    let utf16 = s.encode_utf16().count(); // what C#'s string.Length counts
    let graphemes = s.graphemes(true).count(); // what a reader calls "characters"
    println!("{label:<10} bytes {bytes:>2}  chars {chars:>2}  utf16 {utf16:>2}  graphemes {graphemes}   {s}");
}

fn main() {
    // 1. Four lengths of one string.
    show("ascii", "rule");
    show("accent", "café");
    show("combining", "cafe\u{301}"); // e + COMBINING ACUTE ACCENT: looks identical
    show("emoji", "👍🏽");          // thumbs up + skin-tone modifier
    show("flag", "🇳🇱");            // two regional-indicator letters
    show("cjk", "規則");

    // 2. The bytes and chars behind "café".
    let s = "café";
    println!("2. bytes: {:02x?}", s.as_bytes());
    for (i, c) in s.char_indices() {
        println!("   byte {i}: {c:?} = U+{:04X}, {} byte(s) in UTF-8", c as u32, c.len_utf8());
    }

    // 3. Equal on screen, different bytes: comparison is byte-wise.
    println!("3. \"café\" == \"cafe\\u{{301}}\": {}", "café" == "cafe\u{301}");

    // 4. Slicing is by byte range and must land on char boundaries.
    println!("4. &s[0..3] = {:?}", &s[0..3]);
    println!("   s.is_char_boundary(4) = {}, (5) = {}", s.is_char_boundary(4), s.is_char_boundary(5));
    println!("   s.get(0..3) = {:?}, s.get(0..4) = {:?}", s.get(0..3), s.get(0..4));
    println!("   first char: {:?}, last char: {:?}", s.chars().next(), s.chars().next_back());

    // 5. Case mapping is Unicode-aware and can change the length.
    println!("5. \"straße\".to_uppercase() = {:?}", "straße".to_uppercase());
    println!("   \"İ\".to_lowercase().len() = {} (was {})", "İ".to_lowercase().len(), "İ".len());
    println!("   \"title\".to_uppercase() = {:?} (no culture: same result everywhere)", "title".to_uppercase());
    println!("   eq_ignore_ascii_case(\"VIP\", \"vip\") = {}", "VIP".eq_ignore_ascii_case("vip"));
}

Step 3 — slices of everything, and deref coercion

use std::mem::size_of;

// One parameter type accepts every kind of text (deref coercion does the rest).
fn describe(s: &str) -> String {
    format!("{s:?} ({} bytes)", s.len())
}

// And one parameter type accepts every contiguous run of values.
fn total(amounts: &[i64]) -> i64 {
    amounts.iter().sum()
}

fn main() {
    // 1. &str from a literal, a String, a &String, and a slice of either.
    let owned = String::from("country == NL");
    println!("1. {}", describe("literal"));
    println!("   {}", describe(&owned)); // &String coerces to &str
    println!("   {}", describe(&owned[11..])); // a sub-slice
    println!("   {}", describe(owned.as_str())); // explicit

    // 2. &[T] from an array, a Vec, and a range of either.
    let fixed: [i64; 4] = [100, 250, 40, 120];
    let growable: Vec<i64> = fixed.to_vec();
    println!("2. totals: {} {} {}", total(&fixed), total(&growable), total(&growable[1..3]));

    // 3. A slice is a fat pointer: address + length.
    println!("3. size_of &[i64] = {}, &[i64; 4] = {}, Vec<i64> = {}",
        size_of::<&[i64]>(), size_of::<&[i64; 4]>(), size_of::<Vec<i64>>());

    // 4. Read-only slice methods.
    let s = &growable[..];
    println!("4. first {:?} last {:?} get(9) {:?} contains(&40) {}",
        s.first(), s.last(), s.get(9), s.contains(&40));
    let (head, rest) = s.split_at(1);
    println!("   split_at(1): {head:?} | {rest:?}");
    println!("   windows(2): {:?}", s.windows(2).map(|w| w[1] - w[0]).collect::<Vec<_>>());
    println!("   chunks(3):  {:?}", s.chunks(3).collect::<Vec<_>>());

    // 5. Mutable slices: change elements in place, never the length.
    let mut batch = growable.clone();
    let part: &mut [i64] = &mut batch[1..];
    part.sort();
    part[0] *= 2;
    println!("5. after sort + double first of [1..]: {batch:?}");
    println!("   binary_search(&120) in sorted part: {:?}", batch[1..].binary_search(&120));

    let rule = "  amount >= 100 AND country == NL  ";

Step 5 — what borrowing saves: counting allocations

A global allocator that counts every allocation, and four versions of the same rule tokenizer (split each line into tokens, normalise each condition's field name) run over 10,000 lines:

use std::alloc::{GlobalAlloc, Layout, System};
use std::borrow::Cow;
use std::hint::black_box;
use std::sync::atomic::{AtomicUsize, Ordering::Relaxed};
use std::time::Instant;

// A global allocator that counts every allocation, then defers to the system one.
struct Counting;
static ALLOCS: AtomicUsize = AtomicUsize::new(0);
static BYTES: AtomicUsize = AtomicUsize::new(0);

unsafe impl GlobalAlloc for Counting {
    unsafe fn alloc(&self, layout: Layout) -> *mut u8 {
        ALLOCS.fetch_add(1, Relaxed);
        BYTES.fetch_add(layout.size(), Relaxed);
        unsafe { System.alloc(layout) }
    }
    unsafe fn dealloc(&self, ptr: *mut u8, layout: Layout) {
        unsafe { System.dealloc(ptr, layout) }
    }
}

#[global_allocator]
static GLOBAL: Counting = Counting;

// Approach A: every token becomes its own String; every field is lowercased into a new String.
fn owned(lines: &[String]) -> usize {
    let mut fields = 0;
    for line in lines {
        let tokens: Vec<String> = line.split_whitespace().map(|t| t.to_string()).collect();
        for cond in tokens.chunks(4) {
            let field: String = cond[0].to_lowercase();
            fields += black_box(field).len();
        }
    }
    fields
}

// Approach B: tokens borrow from the line; fields are still lowercased into new Strings.
fn borrowed(lines: &[String]) -> usize {
    let mut fields = 0;
    for line in lines {
        let tokens: Vec<&str> = line.split_whitespace().collect();
        for cond in tokens.chunks(4) {
            let field: String = cond[0].to_lowercase();
            fields += black_box(field).len();
        }
    }
    fields
}

// Approach C: borrow, and only allocate a lowercase copy when the field actually needs one.
fn normalize(field: &str) -> Cow<'_, str> {
    if field.bytes().any(|b| b.is_ascii_uppercase()) {
        Cow::Owned(field.to_ascii_lowercase())
    } else {
        Cow::Borrowed(field)
    }
}

fn borrowed_cow(lines: &[String]) -> usize {
    let mut fields = 0;
    for line in lines {
        let tokens: Vec<&str> = line.split_whitespace().collect();
        for cond in tokens.chunks(4) {
            fields += black_box(normalize(cond[0])).len();
        }
    }
    fields
}

// Approach D: as C, but reuse one token buffer for every line instead of a new Vec per line.
fn reused_buffer(lines: &[String]) -> usize {
    let mut fields = 0;
    let mut tokens: Vec<&str> = Vec::new();
    for line in lines {
        tokens.clear(); // keeps the capacity
        tokens.extend(line.split_whitespace());
        for cond in tokens.chunks(4) {
            fields += black_box(normalize(cond[0])).len();
        }
    }
    fields
}

fn measure(name: &str, lines: &[String], f: fn(&[String]) -> usize) {
    let (a0, b0) = (ALLOCS.load(Relaxed), BYTES.load(Relaxed));
    let result = f(lines);
    let (allocs, bytes) = (ALLOCS.load(Relaxed) - a0, BYTES.load(Relaxed) - b0);
    let best = (0..5)
        .map(|_| {
            let t = Instant::now();
            black_box(f(black_box(lines)));
            t.elapsed().as_secs_f64() * 1e3
        })
        .fold(f64::INFINITY, f64::min);
    println!("{name:<26} {allocs:>7} allocs {:>8.1} KB   {best:>6.2} ms   (checksum {result})",
        bytes as f64 / 1024.0);
}

fn main() {
    // 10,000 rule lines with 3 conditions each; one line in ten spells a field in capitals.
    let lines: Vec<String> = (0..10_000)
        .map(|i| {
            let field = if i % 10 == 0 { "Amount" } else { "amount" };
            format!("{field} >= {} AND country == NL AND tier == gold", i % 500)
        })
        .collect();

    println!("10,000 lines, 30,000 conditions; allocations counted by a global allocator:");
    measure("A: String per token", &lines, owned);
    measure("B: &str tokens", &lines, borrowed);
    measure("C: &str tokens + Cow", &lines, borrowed_cow);
    measure("D: C + one reused Vec", &lines, reused_buffer);
}
10,000 lines, 30,000 conditions; allocations counted by a global allocator:
A: String per token         170000 allocs   7097.5 KB     4.17 ms   (checksum 170000)
B: &str tokens               60000 allocs   4541.0 KB     2.10 ms   (checksum 170000)
C: &str tokens + Cow         31000 allocs   4380.9 KB     1.45 ms   (checksum 170000)
D: C + one reused Vec         1003 allocs      6.3 KB     0.55 ms   (checksum 170000)

Borrowed tokens (B) removed 11 allocations per line. Cow (C) removed the lowercase copies that weren't needed. Reusing one token buffer (D, clear() keeps capacity) removed the rest: 170× fewer allocations and 7.6× faster than the C#-style "a string per token" version. This is the core technique of zero-copy parsing. Chapter 6.2 returns to allocation-aware design, and chapter 7.1 applies it with serde's borrowed deserialization.

Exercise 2 — a zero-copy condition parser ★★☆ product skill

Write fn parse_condition(src: &str) -> Option<(&str, &str, &str)> that splits "amount >= 100" into field, operator and value (operators >= <= == != > <), trims whitespace, rejects an empty field or value, and copies nothing. Prove in a test that the returned field points into the input.

Show solution 
// Split "field op value" into three slices of the input, without copying.
fn parse_condition(src: &str) -> Option<(&str, &str, &str)> {
    // Two-character operators first, so ">=" isn't read as ">".
    for op in [">=", "<=", "==", "!=", ">", "<"] {
        if let Some((field, value)) = src.split_once(op) {
            let (field, value) = (field.trim(), value.trim());
            if field.is_empty() || value.is_empty() {
                return None;
            }
            return Some((field, op, value));
        }
    }
    None
}

fn main() {
    let input = String::from("  amount >= 100 ");
    let (field, op, value) = parse_condition(&input).unwrap();
    println!("{field:?} {op:?} {value:?}");

    // Zero-copy: field and value point into `input`'s own buffer.
    let range = input.as_bytes().as_ptr_range();
    assert!(range.contains(&field.as_ptr()) && range.contains(&value.as_ptr()));

    assert_eq!(parse_condition("country==NL"), Some(("country", "==", "NL")));
    assert_eq!(parse_condition("tier != gold"), Some(("tier", "!=", "gold")));
    assert_eq!(parse_condition("age < 18"), Some(("age", "<", "18")));
    assert_eq!(parse_condition("tier"), None);
    assert_eq!(parse_condition("== NL"), None);
    println!("ok");
}
"amount" ">=" "100"
ok

The two-character operators are tried first, otherwise "amount >= 100" would split at > and give the value "= 100". split_once and trim return slices of src, so the output borrows from the input. That's why the signature needs no lifetime annotation: with one reference parameter, the compiler ties the returned references to it (lifetime elision, chapter 2.11). The operator comes from a literal, a &'static str, which coerces to the shorter lifetime. The pointer-range assertion is how you test zero-copy claims.

Exercise 3 — escape CSV fields with Cow ★★☆ product skill

Write fn escape_csv(field: &str) -> Cow<'_, str>: if the field contains a comma, a double quote or a newline, return it wrapped in quotes with inner quotes doubled; otherwise return it borrowed. Count how many fields of an export were borrowed.

Show solution 
use std::borrow::Cow;

// Quote a CSV field only when it needs it; most fields are returned as-is, borrowed.
fn escape_csv(field: &str) -> Cow<'_, str> {
    if field.contains([',', '"', '\n']) {
        Cow::Owned(format!("\"{}\"", field.replace('"', "\"\"")))
    } else {
        Cow::Borrowed(field)
    }
}

fn main() {
    let fields = ["approve", "amount, net", "say \"hi\"", "NL"];
    let escaped: Vec<Cow<str>> = fields.iter().map(|f| escape_csv(f)).collect();
    println!("{}", escaped.join(","));
    let borrowed = escaped.iter().filter(|c| matches!(c, Cow::Borrowed(_))).count();
    println!("{borrowed} of {} fields borrowed, {} allocated", escaped.len(), escaped.len() - borrowed);

    assert!(matches!(escape_csv("plain"), Cow::Borrowed("plain")));
    assert_eq!(escape_csv("a,b"), "\"a,b\"");
    assert_eq!(escape_csv("say \"hi\""), "\"say \"\"hi\"\"\"");
    println!("ok");
}

Common misconceptions and pitfalls

⚠️ Treating len() as a character count

It's bytes. Use chars().count() for scalar values or graphemes for what users see, and size database columns and UI limits with that difference in mind.

⚠️ Slicing with offsets from outside the string

&s[0..n] with a fixed n ("truncate to 20") panics on multi-byte text. Use s.get(..n), char_indices to find a boundary, or truncate by graphemes for display.

⚠️ &String and String parameters

Take &str. A String parameter forces callers to give up or clone their text; &String rejects literals and slices for no benefit.

⚠️ Reversing or truncating by char

s.chars().rev() separates combining marks from their letters and splits flags and emoji sequences. For anything a user sees, work in graphemes.

⚠️ Comparing user-visible text byte-wise

"café" composed and decomposed aren't ==. Normalize (NFC) at the boundary where text enters the system, and decide on case-folding rules explicitly.

⚠️ A String per token

Allocating a String for every piece of parsed input is the C# reflex. Slice instead, use Cow for occasional changes, and reuse buffers (Lab step 5).

Real-world view: text in your products

🏗 Architecture view
  • Rule parsing is zero-copy: the lexer returns &str tokens into the rule source, and the parser builds an AST that either borrows from the source (with lifetimes, chapter 2.11) or converts the few names it keeps into owned or interned strings at the end.
  • Field names are interned: compiled rules refer to fields by Arc<str> or a numeric id, so evaluation compares integers, not text (chapters 9.2–9.3).
  • Normalize at the edge: decide once, where requests enter (API, file import), on Unicode normalization (NFC), trimming and case rules. Inside the engine, text is then compared byte-wise, fast and predictably, with no culture surprises.
  • Payloads stay bytes until needed: the workflow engine stores step payloads as Vec<u8>/Bytes and only validates or deserializes them when a step reads them (chapters 7.1, 10.3).
  • Review checklist: &s[..n] with outside offsets; len() used as a character count; String/&String parameters; to_string() per token in parsers; to_lowercase where ASCII-only eq_ignore_ascii_case was meant; user-visible truncation by char.

Summary

  • String owns growable UTF-8 text (24 bytes: pointer, length, capacity); &str borrows it, or a literal (16 bytes: pointer, length). Store and return String; accept &str.
  • Slices &[T]/&mut [T] are bounds-checked fat pointers into arrays and Vecs. Deref coercion lets one &str or &[T] parameter accept every caller.
  • Text has several lengths: bytes (len), chars, UTF-16 units (C#'s Length) and graphemes. There's no s[i]; slicing is by byte range and panics mid-character (get returns None).
  • Slices are borrows: they can't outlive or watch their String change. + consumes its left side; format! doesn't. Cow returns borrowed text when possible and owned text when necessary.
  • Borrowing, Cow and buffer reuse took a tokenizer from 170,000 allocations to 1,003, and from 4.17 ms to 0.55 ms. Comparison and case mapping are byte-wise and culture-free, unlike .NET's defaults.
