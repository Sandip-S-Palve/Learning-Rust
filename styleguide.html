Callouts

💡 Why this matters

A .NET service leaks memory through forgotten event handlers or undisposed streams. Rust's ownership rules make most of those leaks impossible to write by mistake.

🧭 Analogy

Ownership is like the single signed original of a contract. You can hand it to someone else (a move), or let people read it under supervision (a borrow), but there is only ever one original, and when its owner leaves, it is shredded.

🟣 Coming from C#/.NET

Drop plays the role of IDisposable.Dispose, except you never call it and can't forget it: the compiler inserts the call at the end of the owner's scope.

⚠️ Pitfall

Calling .clone() to silence the borrow checker compiles, but it may copy megabytes on every call. Find out why the borrow failed first.

⚠ Verify

Used whenever a fact could not be confirmed against a primary source on the stamp date. Example: “The exact release that stabilised feature X is believed to be 1.88 — check the release notes.”

Layered explanation

Basic

Every value has exactly one owner. When the owner goes out of scope, the value is dropped.

Intermediate

Assigning a String to another variable moves it: the pointer, length and capacity are copied, the heap data is not, and the old variable becomes unusable.

Deep dive: what the compiler actually generates

A move is a plain bitwise copy of the stack part of the value (here 24 bytes on 64-bit targets). What makes it a move rather than a copy is the compiler's static tracking: it records the source as uninitialised and refuses later reads. If a move happens only on some paths through the code, the compiler adds a hidden drop flag to decide at runtime whether to call Drop.

Exercises

Exercise 1 ★☆☆ warm-up

Change the program above so that both s1 and s2 can be printed. Give two different solutions and say which one allocates.

Show solution 
// 1) Clone: allocates a second heap buffer
let s1 = String::from("hello");
let s2 = s1.clone();
println!("{s1} {s2}");

// 2) Borrow: no allocation, s2 is a reference to s1
let s1 = String::from("hello");
let s2 = &s1;
println!("{s1} {s2}");

Prefer borrowing unless you really need two independent owners.

Check your understanding

Multiple choice
After let b = a; where a: String, what is copied?
  1. The whole heap buffer
  2. Nothing — b is an alias for a
  3. The pointer, length and capacity
  4. Only the pointer

Wrong: copying the heap data is what .clone() does, and it is never implicit for String.

Wrong: Rust has no implicit aliasing. Sharing needs an explicit reference (&a).

Correct: the 3-word stack header is copied bitwise, and a becomes unusable.

Wrong: length and capacity are part of the value too; b needs them.

Scenario
Your team is porting a C# cache that hands the same Customer object to many request handlers running on a thread pool. Which Rust type fits best as the shared handle?
  1. Rc<Customer>
  2. Arc<Customer>
  3. Box<Customer>
  4. &'static Customer created with Box::leak on every insert

Wrong: Rc is not Send, so the compiler will not let it cross threads.

Correct: atomic reference counting gives shared ownership across threads, and the last handle frees the value.

Wrong: Box has one owner, so it can't be shared.

Wrong: it compiles, but it leaks every entry ever cached — memory that is never reclaimed.
